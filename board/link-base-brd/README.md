# link-base-brd

Base board of the **Link** platform: MCU, display, power and battery
management. It carries no field interface of its own — that is the job of the
interface module it hosts, which makes the same base a Link-LR, a Link-485, or
whatever comes next.

Part of [`link-hardware`](../../README.md). See the repository README for
naming, versioning and release conventions.

## Design

| Function | Part |
|---|---|
| MCU | ESP32-S3-WROOM-1-N16R8 (16 MB flash, 8 MB PSRAM) |
| Battery charger | BQ24074RGT — USB or Li-ion input, power path |
| Fuel gauge | MAX17048G+ |
| Buck converter | TPS62821 |
| Real-time clock | PCF8563T + 32.768 kHz crystal |
| Backlight driver | CAT4104V-GT3 |

Power comes from USB-C or a Li-ion cell, with charging and power-path
management on board — the device keeps running while charging.

## Connectors

| Ref | Role |
|---|---|
| J3 | Base↔module interface (2×10, 2 mm) |
| J5 | USB-C (USB 2.0) |
| J6, J7 | Display FPC |
| J1 | Battery (JST-XH) |

**J3 is the platform contract.** Its pinout, the mounting footprint and the
module outline are what every interface module must satisfy. Breaking any of
them is a MAJOR version bump, and means supporting two incompatible fleets.

## Status

Pre-production (`0.x`). The design is under validation on our own bench; all
interfaces may still change without a MAJOR bump.

## Files

Design sources are the KiCad project in this folder. `outputs/` holds the
fab-agnostic exports of the last freeze — schematic PDF, BOM, position file,
gerbers and STEP.

They are regenerated by running `outputs.kicad_jobset` from the KiCad
project window. Output names carry the revision read from the schematic title
block, so they cannot drift from the sources.
